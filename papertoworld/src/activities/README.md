# In-world Paper Siege

Ported from `papertoworld/games/siege.js` at local `main` commit `24acb1c`. Remote GitHub branches were checked on 2026-10-30: `main` and `site-release`; no separate paperball branch exists. The user confirmed this paper-cannon castle game was the intended activity.

`createPaperSiege(THREE)` returns `start(host)`, `update(dt)`, `stop()`, pointer hooks, `wheel(event)`, `key(event, down)`, `refreshTerrain()` and a `debug` getter. The host uses `createLandscapePlay(host)` to build the castle automatically inside the reserved clearing; walking and camera controls stay active. `freeRoam: true` on the lower-level Siege host hides its legacy HUD and skips camera/intro/outcome handling. There is no registry, page navigation, renderer creation or landscape visibility/matrix manipulation in this port. The orchestrator exposes a one-click Throw bomb action, optional Aim / distance controls with a predicted arc/blast ring, and a rain toggle during walking. Clicking/tapping a spot selects a target; Throw or optional Space confirms. B and Escape are optional aim shortcuts. Camera drags and the touch joystick do not throw. Landscape change counts replace the castle score. Prediction is cached until the aim/world/physics revision changes, throttled to 10 Hz while moving. No entry menu or separate gameplay mode is used.

`host` supplies the shared `scene`, `camera`, `renderer`, HUD container `hud`, `THREE`, `C: {PW, HW}`, `heights(): {grid,n,size}`, `hAt`, `surfaceY`, `isWater`, `waterAt`, season/night getters, an audio adapter (`ensure`, `pluck`, `burst`, `ctx`, `out`, `muted`), and `exit()`. `tweening` can pause the game camera during host transitions. Heights use the main terrain row order and world units. Three's material aliases should use the same node material classes as `src/app.js`.

Required `activitySite = {castle:{x,z}, cannon:{x,z}}` stays fixed across levels. Reserve a radius of 1.8 at the castle, .55 at the cannon, and a .6 half-width firing lane. Recommended separation is 3.8 units. Leave room behind the cannon for the camera. The host places this before tree/building placement, and checks dry walkable access. The activity builds flat plinths above the highest sampled terrain, without editing its height field.

Optional `onImpact({x,y,z,radius,power,kind})` receives one event per projectile. Radius is capped at .6 world units, power at 1. Bombs notify at detonation, stones/pellets at their first meaningful collision. Events run after the physics/contact iteration. The host may change terrain/vegetation and retain it until Regrow; the activity refreshes Cannon heightfield caches afterward. Call `refreshTerrain()` after other host terrain edits while playing.

Legacy programmable GLSL point sprites were replaced with the renderer's `createPointCloud` TSL billboard implementation, covering dust, explosion light and aim dots in WebGPU and WebGL2. Cannon-es 0.20.0 and its MIT license are preserved in `papertoworld/vendor/` from the source branch. No third-party models, network dependencies or additional lights are needed.

CPU tests in `tests/paper-siege.test.mjs` use real Three transforms and Cannon physics with inert DOM/canvas adapters: fixed site across levels, target defeat, bounded one-shot terrain impact, heightfield refresh, world preservation, idempotent cleanup and exit during loading. Browser integration checks belong to the shared app QA run.

`applyExternalBlast({x,y,z,radius,power})` applies free-walk bomb damage to castle bodies/targets without moving the camera. The orchestrator routes each landscape bomb through this call and the host terrain-impact callback. Sleeping castle physics stops stepping until an external blast wakes bodies. `build(site)` returns a readiness Promise and generation tokens cancel late async completion after Regrow/clear.
